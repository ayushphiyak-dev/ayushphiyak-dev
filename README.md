### Development Philosophy

**01 — The worst frame defines the interface**
Loading, empty, and error states get the same care as the primary flow.

**02 — Motion earns its place through clarity**
A transition survives only if it communicates state or hierarchy. Otherwise, it's cut.

**03 — Constraints precede components**
Spacing, type, and color scales are defined before a single component is built.

**04 — Small releases, real feedback**
A working version in front of users outperforms a polished spec no one has tested.

**05 — Performance is part of the design**
An interface that stutters isn't finished, regardless of how it looks.
